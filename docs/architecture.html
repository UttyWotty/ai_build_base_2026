OSI Opsight Intelligence

At 2 a.m., two machines need the last spare part. OSI decides who gets it, covers the other, and proves it paid off.

Submission due 18 Oct 2026Model Gemini 3.8 Flash Agents Google ADKRuns on Cloud Run + Vertex AI

The 30-second pitch

Predicting the failure is the easy part; getting the part in time is not. Whether the line keeps running depends on stores, purchasing, and customer service. OSI carries the alert across all three. A team of Gemini agents checks the spare part, the supplier, and the customer orders, prices every option, and drafts the plan. A person approves it. On four months of plant data it avoided 662 hours of downtime and saved $197,949 net, with its mistakes counted.

If a judge remembers one sentence: the expensive mistakes happen between departments, and this is an AI team that works between them.

The problem

A sensor says a spindle bearing on line 2 will fail in about a day. That warning window is called the P-F interval: the time between "we can see it failing" and "it failed". The alert is useful only if the repair fits inside that window. Whether it fits depends on three questions that live in three other systems:

Stores

Is the bearing on the shelf, or already promised to another machine?

Purchasing

When will the open order really arrive, given how this supplier usually delivers?

Customer service

Which customer orders does this line make in the next few days?

Today, answering that takes hours of phone calls while the window runs out. Most AI tools answer one department's question. Ours connects them.

How it works

The product is a loop with four steps. Each step is real code you can point to.

  1. Sense. A machine-learning model (gradient boosting, not an LLM) scores every machine from its sensors. It caught 27 of 41 failures, with 0.16 false alerts per machine per month and a median warning of 86 hours.
  2. Reason. A team of Gemini agents looks into the alert using governed tools only: sensor evidence, inspection photos, spares at both sites, the supplier's delivery record, and the customer orders at risk.
  3. Act. The team proposes a work order, a parts action, and a note to the customer. Nothing happens until a person approves.
  4. Close the loop. The approval changes the simulated world: a transfer leaves the other site's shelf, the conflict clears, and once the clock passes the failure, the app shows the outcome against doing nothing.

In Live mode the plant replays in time. With Autopilot on, each new alert pauses the clock while the agents work, so the plan is ready by morning.

The system

The parts, in one line each

  • Two synthetic worlds. A two-site plant (US1, DE1) and a four-plant supply network, generated from seeds, both ending on 28 Sep 2026. No real company data.
  • Governed bridge (semantic/bridge/bridge.yaml) links plant sites to supply plants, machine parts to spares and suppliers, and lines to the customer parts they make.
  • Metric compiler. Supplier on-time delivery is defined once in YAML and compiled to SQL. The model picks a metric; it never writes SQL.
  • Impact analysis prices five ways to get the spare: own stock, open order, air transfer, broker, new order. Each is extra spend plus lost contribution from the outage.
  • Gemini reader turns supplier emails, PDFs, and inspection photos into schema-checked JSON.
  • One container. FastAPI serves the API, the live agent stream, and the React app. Gemini runs on Vertex AI under the service account, so no API key is deployed.

The agent team

This uses Google's Agent Development Kit as designed: a ParallelAgent inside a SequentialAgent (src/backend/copilot/services/agent_team.py). Free questions on the Copilot page go to a single agent with all nine tools instead. A team run costs about twelve model calls; a single run about five. If one Gemini model runs out of quota before its first step, the run restarts on a backup model and the trace says so.

One alert, start to finish

This is the demo story. It comes straight from the generated data; nothing is planted on top.

  1. 25 Jul 2026, 02:00Two spindle-bearing alerts at US1 need the one bearing set on the shelf. The replacement is on order from supplier V10001.
  2. 02:00, clock pausedAutopilot starts the team. The procurement lead finds V10001 was on time for only 66.1% of its lines in the last 90 days, and Gemini has read its delay notice: the new date is 8 August.
  3. 02:00, plan readyThe lead gives the shelf set to the overdue alert and covers this one with an air transfer from DE1 for $650. Waiting for the order would mean 190 hours down and four customer order lines at risk.
  4. ApprovalA person approves. The bearing set leaves the DE1 shelf in the simulation.
  5. 26 Jul 2026, 10:00The spindle fails as predicted. With the transfer, the line is down 26 hours instead of 230. Saved: $100,077.

Why the numbers can be trusted

No invented numbers

Every number in an answer is checked against the tool results before the answer gets the "Verified" badge.

No SQL from the model

Supplier metrics compile from governed definitions and carry a SQL fingerprint.

No peeking at the future

Every tool answers as of the demo clock. Outcomes count only once they are in the past.

No silent actions

Agents only propose. A proposal's numbers come from the analysis, not the model's text. People approve.

Quality evidence: 438 backend and 10 frontend tests, offline tests of the real ADK runner with scripted models, and an eight-scenario agent evaluation (make eval, 7 of 8 on a local model; the full Gemini score is still to run).

Words you will hear

P-F interval
Time from when a failure becomes detectable (P) to when it happens (F). The window the plan must fit in.
OEE
Overall equipment effectiveness: availability times performance times quality. The plant's standard health score.
MES, CMMS, ERP, TMS
Production, maintenance, business, and transport systems. Each department's own source of truth.
OTD
On-time delivery: the share of a supplier's order lines that arrived on time.
Governed metric
A number defined once in a reviewed YAML file, so every answer computes it the same way.
Point in time
Every query sees only data up to the demo clock, as a real plant would.
ADK
Google's Agent Development Kit, the framework that runs the agents and their tools.
Vertex AI
Google Cloud's platform for calling Gemini with a service account instead of an API key.
Cloud Run
Google Cloud service that runs our container and gives it a public URL; it scales to zero when idle.
Server-sent events
How the browser receives each agent step live while the team works.
